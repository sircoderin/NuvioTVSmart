## #1055: outgoing picker frame

The candidate snapshots route/resume/candidate data, quiesces picker loading/rendering on webOS, hides the picker without destroying its route snapshot, and permits two animation-frame opportunities before ordinary Router navigation. There is no fixed timer. Back, replacement selection, cleanup and suspension invalidate the selection; canceled frame waits settle. Native scroll is saved before hiding. Resume lookup remains intact. Tizen retains the no-frame-wait path; no Tizen device validation is claimed.

The loading indicators changed upstream between 1.2.3 and 1.2.4: SVG indicators replaced the multiple animated spokes. New results must not be assumed equivalent to the historical animation experiment.

Natural candidate selections initially had all sources loaded (100 cards), so they are excluded from the pending-source comparison. Controlled runs hold the response stage of the same two addon requests using CDP while selecting the same Abbott Elementary S3E1 Comet 1080p card: 82 cards, two sources pending, six picker animations. This controls response arrival, not a measurement of natural addon latency. Responses are released and interception disabled after each run.

Selection-to-player timing means selection to the next player animation-frame callback, not a physical display scanout. GPU swap duration is the overlap of `NativeViewGLSurfaceEGL:RealSwapBuffers` with the renderer task containing player mount. It is not all GPU work.

| Controlled run | Selection → next player frame | Mount task / CPU | GPU swaps during mount / overlap |
| --- | --- | --- | --- |
| Upstream 1.2.4 | 2,002 ms | 1,971 / 1,190 ms | 4 / 117 ms |
| Stream candidate | 1,237 ms | 959 / 682 ms | 0 / 0 ms |

One controlled run per build is insufficient to establish a reliable saving. Another natural upstream sample with the same card/pending counts reached the next player frame in 1,094 ms, illustrating the variation. The candidate permits a hidden-frame interval (176 ms in the controlled sample); this is measured scheduling, not a fixed delay. Playback reached 1080p and was paused; the candidate's final readiness sample had fallen from 4 to 2. Back returned to Stream in a separate TV check, but a full device regression pass, scroll restoration and automatic-selection validation are not complete. Deterministic unit coverage is not a substitute for those device checks.

**Disposition:** no reliable solution demonstrated; do not merge or describe #1055 as fixed. A follow-up comment on #1055 reports the inconclusive result and invites closure.

## #1059: first-visit artwork

Setup: Modern Home, Hero enabled, focused-poster expansion disabled, 60 catalog rows. Fresh app launch, wait for row count to remain stable for 16 seconds, move from Continue Watching into the first catalog row, then 25 Down keys with 400 ms between completed CDP key dispatches. Image/network/graphics caches are not forcibly cleared. Focus finishes on the same row in the samples.

Temporary instrumentation records source assignments, load/error events and natural dimensions without per-image geometry reads. Opaque source hashes correlate assignments to trace `PaintImage` events without putting artwork URLs in the summary. Hero assignments/loads are included rather than attributing all image work to posters. One uninstrumented control also reproduces the stalls.

| Upstream run | Median / p95 / max key to next frame |
| --- | --- |
| Instrumented 1 | 135 / 2,100 / 2,135 ms |
| Uninstrumented control | 247 / 3,224 / 3,987 ms |
| Instrumented 2 | 115 / 280 / 387 ms |
| Instrumented 3 | 212 / 2,215 / 3,254 ms |

The first two instrumented runs assigned 185–186 images, mostly in groups of eight, sometimes sixteen. Posters commonly had natural dimensions 600×900 or 680×1000. Correlated paint events in the second run used source crops around 586×900 or 650×1000 and destination sizes around 226×339 or 230×339 CSS pixels. DPR 2 must be considered before labeling those resolutions excessive.

Two renderer tasks in the second run (586 and 1,002 ms) followed eight assignments within the preceding second and overlapped seven/eleven image-decode tasks. Across threads, summed `ImageDecodeTask` durations were about 13.2–13.8 seconds in these runs; this sum is not elapsed wall time. Similar decode aggregates accompanied very different key timing. Correlation supports a pacing experiment, not a causal claim that source assignment itself consumes those seconds.

The Home candidate reuses the existing priority queue on non-legacy webOS with at most two source assignments per frame. It preserves focus scheduling, neighborhood bounds, image URLs/sizes, runtime policy, and Tizen/legacy paths. Full neighborhood scans remove obsolete queued entries in place; partial same-row scans retain skipped neighbors. Discarded images retain `data-src` for rediscovery. This caps assignments, not concurrent decoding or GPU uploads.

**Initial checkpoint:** the Home candidate passed unit/review/build checks but had not yet been installed or measured. The subsequent device check below supersedes that status. Do not merge the candidate or call #1059 fixed.

## Paused architectural checkpoint

The user requested a pause before further deployments/comparisons. Prioritize understanding Home's overall work/memory bounds over accumulating micro-optimizations. The reference `iqui27/nuvio-native-legacy` uses C/SDL2/GLES2 on LG; its README describes local startup caching and a RAM-dependent texture budget. The user's observations about a roughly 32-catalog recommendation, smaller low-RAM limits and profile/startup preloading still need source verification.

Next investigation, if requested: inspect that client's actual catalog limits, visible-row/card rendering, preload/decode scheduling, texture residency/eviction and per-key work; identify which principles transfer to the DOM client. Distinguish network preloading from mounting/rendering all artwork. Do not silently cap the user's catalogs or promise native parity. Compare bounded DOM residency/row virtualization against simply pacing assignments, using the same catalogs and measured TV flows.

At the architectural pause, clean upstream **1.2.4 (`d4dcb29`)** was installed and all temporary instrumentation had been removed.

The original performance-fork **1.2.3** was subsequently restored and verified, before the separately authorized upstream merge and deployment of the performance fork **1.2.4**. Following the final Home candidate check, that merged fork 1.2.4 was restored again: installed metadata, bundle, CSS and configuration match its extracted IPK; Home is visible, video is paused and no active experiment probes remain.

## Final disposition

- **What we tried for #1055:** retire the outgoing webOS picker before player navigation, using cancellation-safe animation-frame opportunities rather than a fixed delay. One matched sample improved, but baseline variation prevented a reliable benefit claim.
- **What we tried for #1059:** pace Home artwork source assignments to two per animation frame and prune obsolete queued entries, without changing artwork sizes, URLs or catalog limits. This changed assignment pacing but did not eliminate multi-second navigation stalls.
- Neither experiment is a reliable solution. Retire the experimental source checkout and branch; retain this explanation and local measurement evidence. Request closure of the issues for now, and update them if a reliable solution is found later. No further tests or experimental deployments are planned.

## Verification and limits

- All discovered test files run through `node --test`: 15 reported tests pass, including the handoff and image-queue assertion suites. Repository lint and webOS build/package pass.
- Latest upstream has no `test:unit` script. The inherited `npm test` wrapper references missing files; it is not reported as passing.
- Small samples, cache variation and asynchronous network/video readiness limit conclusions. Neither candidate is a proven universal fix or evidence of native-client parity.
- No experimental code was published. Issue follow-ups communicate the inconclusive results and invite closure without claiming the underlying bugs are fixed.
